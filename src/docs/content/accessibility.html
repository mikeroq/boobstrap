Guidance

Accessibility

Boobstrap supplies visible focus treatment, reduced-motion safeguards, accessible color foundations, and .bs-sr-only. Your markup still owns semantics and behavior.

  • Use native elements first: <button> for actions and <a> for navigation.
  • Associate every form control with a visible <label>, or use .bs-sr-only when the visual design cannot accommodate one.
  • Add aria-label to icon-only buttons.
  • Use role="status" for non-urgent dynamic alerts and role="alert" for urgent messages.
  • Do not rely on color alone to communicate state; pair it with text or an icon.
  • When overriding tokens, re-check text and focus-ring contrast in both themes.
Motion preference built in

The base reset reduces animation and transition durations when the user enables prefers-reduced-motion: reduce.

Name icon-only controls

The SVG is decorative; the button carries the action name announced by assistive technology.

HTML · Accessible icon button
<button class="bs-btn bs-btn-secondary bs-btn-icon" type="button" aria-label="Delete attachment"><svg class="bs-icon" viewBox="0 0 24 24" aria-hidden="true"><path d="M3 6h18M8 6V4h8v2m-9 0 1 14h8l1-14" /></svg></button>

Connect descriptions and errors

Use IDs and aria-describedby so helper and validation text are announced with the control.

Used for account recovery.Enter a complete email address.

Choose the right live-region role

Use status for polite updates and reserve alert for urgent information that needs immediate announcement.

Native first

Start with the correct element and input type. Native semantics, keyboard behavior, and form participation are difficult to recreate accurately.

State

Keep aria-expanded, aria-selected, aria-pressed, aria-invalid, and hidden synchronized with visible state.

Test

Check keyboard-only operation, visible focus, zoom, reduced motion, both themes, and at least one screen reader for critical workflows.
