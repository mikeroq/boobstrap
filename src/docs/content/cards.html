Cards

Cards establish a contained surface with composable header, content, and footer regions. Header and footer are optional; add title, description, and action slots only when the card needs them.

Structure

Use .bs-card-header, .bs-card-content, and .bs-card-footer in that order. Header and footer are optional; content can stand alone.

Header slots

Place .bs-card-title, .bs-card-description, and an optional .bs-card-action directly in the header. The action aligns independently without disconnecting the description from its heading.

Compatibility

.bs-card-body remains a supported padded content region, and .bs-card-text remains available for muted copy. Prefer the explicit content and description names in new structured cards.

Accessibility

Use <article> only for standalone content, connect its heading with aria-labelledby, and keep every action a native link or button. Never nest extra controls inside .bs-card-link.

Content-only card

Header and footer are optional. Use the content region by itself when the card needs one uninterrupted block.

Release notes

A concise summary belongs inside the same content surface.

Complete structured card

Compose an optional header and footer around the content region. The header aligns its title and description with an independent action slot; the footer wraps related actions naturally.

Header and content without a footer

Omit the footer when the card has no bottom actions. Header actions remain real controls and descriptions stay associated with the card heading.

Card API

Cards use one surface with explicit, composable regions. The header and footer are optional; every card can contain only .bs-card-content when no additional structure is needed.

ClassPurpose
.bs-cardSurface, border, radius, clipping, and default elevation.
.bs-card-headerOptional responsive grid for the title, description, and action slots.
.bs-card-titleHeading slot within a card header or content region.
.bs-card-descriptionMuted supporting copy associated with the header title.
.bs-card-actionOptional header action aligned independently at the inline end.
.bs-card-contentPrimary padded content region; works with or without a header and footer.
.bs-card-footerOptional wrapping row for related actions, metadata, or status.
.bs-card-raisedStronger shadow for elevated or featured content.
.bs-card-subtleQuieter surface and border treatment for secondary or nested content.
.bs-card-compactReduces inset spacing consistently across simple or structured card regions.
.bs-card-linkMakes a single-destination anchor behave and focus like an interactive card surface.
.bs-card-bodyBackward-compatible padded content region.
.bs-card-textBackward-compatible muted supporting-copy treatment.
