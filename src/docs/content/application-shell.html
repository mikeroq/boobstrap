Application shell

An application shell establishes the persistent frame around product content. These patterns compose Boobstrap navigation and layout primitives; they do not replace the underlying components. See the Sidebar guide for sidebar variants, menu anatomy, responsive behavior, controller methods, and the complete class reference.

Choose where the product identity lives.

Use a stacked shell when one global header owns branding across the full viewport. Use a sidebar-first shell when the full-height navigation rail owns the brand and the main header only needs to expose the collapse control.

Choose a variation

VariationBrand placementHeader relationshipBest fit
StackedGlobal headerThe navigation rails begin below the full-width header.Documentation, admin tools, and products with shared global navigation.
Sidebar-firstSidebar headerThe sidebar header and main header share one aligned height.Dashboards and workspaces where primary navigation defines the product frame.

Stacked shell

The global header spans the viewport and owns the primary sidebar control, so the start and end rails begin directly beneath it. The navigation rail has no duplicate sidebar header; section labels use the same .bs-nav-heading treatment as the documentation site.

Place the brand once

Keep identity in the global header for a stacked shell or in .bs-sidebar-header for a sidebar-first shell. Do not duplicate it across both regions.

Share one header height

Applying .bs-navbar to the sidebar header gives both sidebar-first header regions the same 4rem sizing contract and aligned border.

Keep mobile behavior complete

Pair .bs-sidebar-drawer with a named toggle and backdrop so focus, Escape dismissal, scroll locking, and state remain synchronized.

Use the component reference

For menu variants, collapse modes, custom properties, data attributes, and controller events, continue with the Sidebar guide.

Composition reference

ClassRole in the shell
.bs-navbarCreates the global or contextual header and establishes the shared sidebar-first header height.
.bs-sidebar-layoutPlaces primary navigation beside a flexible main surface.
.bs-sidebar-mainAllows the application content region to grow and shrink safely.
.bs-sidebar-headerHolds product identity only in the sidebar-first variation.
.bs-sidebar-contentProvides the independently scrolling navigation region.
.bs-nav-headingLabels navigation sections consistently with the documentation shell.
.bs-sidebar-end.bs-sidebar-tocAdds an optional compact page-outline rail to a stacked shell.
.bs-sidebar-collapsibleEnables the sidebar-first rail to collapse on desktop.
.bs-sidebar-drawerTurns primary navigation into an off-canvas drawer on smaller viewports.
.bs-sidebar-backdropProvides the drawer's external dismiss target.

These are the composition-level contracts used by the examples. The Sidebar guide remains the source of truth for the complete sidebar API.
